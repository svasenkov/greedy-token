# Зачем greedy-token

**English version:** [WHY.md](WHY.md)

## Проблема (ELI5)

Вы платите умному дорогому ассистенту **за слова**.

Большинство дней вы спрашиваете мелочи: «где этот флаг?», «проходит ли проверка?», «что в доке про X?». Сейчас эти мелочи часто уезжают в **тот же дорогой чат**, что и нормальная архитектура — и вы платите цену архитектуры за поиск строки.

Некоторые команды вешают *вторую* модель, которая судит первую. Качество это может поднять. Но **не** отменяет frontier-цены за grep.

## Как решаем

**Сначала спрашиваем: а модель вообще нужна?**

```text
Skills / Rules / docs search / ADR
  → rg / jq (быстрые tools) → Python-скрипты
  → Ollama (локальная дешёвая LLM, если надо)
  → и только потом Claude / Cursor
```

| Шаг | Простыми словами |
|-----|------------------|
| Tools / скрипты | Дёшево и быстро. Поиск по репо, проверка — без модели. |
| Локальная LLM | Офлайн и дёшево, но медленнее. Когда нужен «чуть ИИ», не на каждый lookup. |
| Дорогой чат | На сложные ~3%: wiring, дизайн, суждения. |
| Модель-судья | На **релизах продукта**, не на каждом внутреннем прогоне. |

Это и есть greedy-token: роутер рядом с coding-агентом, чтобы рутина не жгла дорогой путь.

**Главная продуктовая ценность сейчас:** повторяющаяся задача → **crystallize** в проверяемый детерминированный скрипт (+ роут). В следующий раз → **0 LLM**. Эвристический роутинг и MCP — обвязка вокруг этого цикла, а не host-level pre-router, который мог бы пропустить модель Cursor (публичного API для этого нет).
